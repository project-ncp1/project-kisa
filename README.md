<로컬 개발 환경 기반 점검 스크립트 작성 및 대상 서버 적용>
=>본 점검 스크립트는 VS Code 기반 로컬 개발 환경에서 작성되었으며,
사전 테스트를 거친 후 Rocky Linux 대상 시스템에 배포하여 실행하였다.
이를 통해 운영 환경에 직접적인 영향을 주지 않도록 점검을 수행하였다.

🔧 포트폴리오용 수정 예시 (그대로 써도 됨)
🔹 프로젝트 진행 중 어려웠던 점 및 해결 과정
1. GitHub 인증 방식에 대한 이해 부족

초기에는 VM 환경에서 GitHub로 git push를 수행할 때
계정 비밀번호를 입력하면 되는 것으로 오해하여
정상적으로 push가 되지 않는 문제가 발생하였다.

원인을 조사한 결과, GitHub에서는
비밀번호 기반 인증이 중단되고 Personal Access Token(PAT)을 사용해야 한다는 점을 알게 되었고,
토큰 발급 및 인증 방식으로 전환하여 문제를 해결하였다.

→ 이를 통해 GitHub 인증 정책 변화와 보안 강화 흐름에 대해 이해하게 되었다.

2. Git 기본 워크플로우 미숙으로 인한 충돌 문제

프로젝트 초반에는 git add 이후 git commit을 수행하지 않은 상태에서
원격 저장소와 동기화를 시도하여
로컬과 원격 저장소 간 히스토리 충돌 문제가 발생하였다.

또한 VM 환경에서 기존 레포지토리와
히스토리가 다른 상태로 push를 시도하면서
git pull origin main --allow-unrelated-histories 옵션을 사용하여 병합을 수행하였다.

→ 이 과정을 통해 Git의 commit 단위 관리와 브랜치/히스토리 개념을 명확히 이해하게 되었다.

3. 로컬 작업 경로 혼동으로 인한 반영 실패 문제

VS Code에서 레포지토리를 복사하여 별도의 디렉터리에서 수정한 뒤
기존 로컬 경로의 스크립트를 실행하면서
변경 사항이 적용되지 않는 문제가 발생하였다.

문제 분석 결과,
실행 경로와 수정 경로가 서로 다르다는 점을 인지하지 못한 것이 원인이었으며,
이후 작업 디렉터리 기준을 명확히 하여 해결하였다.

→ 이를 통해 실행 환경, 작업 디렉터리, 로컬 저장소 구조의 중요성을 체감하였다.
